# 개발 환경 확인 목록

각 항목을 직접 확인한 뒤 체크하세요. 이 목록은 환경과 작업 규칙을 확인하기 위한 문서입니다.

- [ ] VS Code 또는 다른 편집기에서 현재 작업 폴더(macOS: `~/Documents/flutter-project/study_planner`)를 열었다. — 확인 방법: 편집기의 프로젝트 루트에 `lib/`, `docs/`, `pubspec.yaml`이 보이는지 확인한다.
- [ ] 사용하는 Codex 환경(데스크톱 앱 또는 VS Code 확장)에 실습 계정으로 로그인했다. — 확인 방법: Codex의 계정 화면에서 실습용 계정으로 로그인되어 있는지 확인하며, 계정 정보는 이 문서에 적지 않는다.
- [ ] 작업 폴더 맨 위에 `AGENTS.md`가 있다. — 확인 방법: 프로젝트 루트에서 `AGENTS.md`를 열어 이 Flutter·Dart 프로젝트의 작업 규칙이 적혀 있는지 확인한다.
- [ ] 새 대화에서 Codex가 `AGENTS.md` 규칙을 요약했다. — 확인 방법: 파일 구성, 도구 제한, 허락이 필요한 작업, 완료 기준을 요약해 달라고 요청하고 실제 규칙과 비교한다.
- [ ] Codex가 규칙에 어긋나는 React·Bootstrap 설치 요청에 규칙과의 충돌을 설명하거나 규칙 변경 여부를 되물었다. — 확인 방법: 설치하지 말고 적합성만 판단해 달라고 요청한 뒤, Dart 소스 제한을 설명하고 설치하지 않았는지 확인한다.
- [ ] Codex가 허락이 필요한 작업과 사전 안내가 필요한 작업을 구분한다. — 확인 방법: 요청에 없는 새 파일·폴더 생성, 저장소 밖 파일 접근, 파일 삭제·Git 기록 변경 전에는 허락을 받고, 패키지 설치 전에는 이름과 이유를 알리는지 확인한다(이미 요청한 파일 생성과 일반 확인 명령은 다시 허락받을 필요가 없다).
- [ ] `docs/plan.md`와 `docs/prompt-design.md`가 있다. — 확인 방법: 두 문서를 열어 기획과 요청 설계를 읽을 수 있는지 확인하고, 대화와 다르면 최근 사용자 결정을 우선한다.
- [ ] `git --version`이 동작한다. — 확인 방법: 작업 폴더의 터미널에서 `git --version`을 실행해 Git 버전이 출력되는지 확인한다.
- [ ] Flutter·Dart 명령을 사용할 수 있다. — 확인 방법: 작업 폴더의 터미널에서 `flutter --version`과 `dart --version`을 실행해 각각 버전이 출력되는지 확인한다.
- [ ] Chrome이 열리고 Flutter 웹앱을 실행할 수 있다. — 확인 방법: 작업 폴더의 터미널에서 `flutter run -d chrome`을 실행해 Chrome에서 앱 화면이 나타나는지 확인한다.
- [ ] 코드·문서·예시 데이터에 개인정보, 비밀번호, API 키, 토큰이 없다. — 확인 방법: 해당 파일을 검토해 실명·전화번호·주소·학번과 비밀값이 없는지 확인하고, 실제 선수 이름과 기록은 공개 경기 자료로 확인하고, 개인 연락처·비밀값이 없는지 확인한다.
